## Deviations from the suggested structure, and why

| Suggested                                                    | Chosen                                                                                  | Reason                                                                                                                                                                                                                                                                               |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Root `prisma/`                                               | `packages/db/prisma/`                                                                   | Makes the database a workspace package with its own scripts and a typed client export consumed by the API and the seed. Root-level Prisma would sit outside the package graph.                                                                                                       |
| `packages/types`                                             | Merged into `packages/shared`                                                           | Types are inferred from the Zod schemas (`z.infer`), so a separate types package would duplicate them.                                                                                                                                                                               |
| `packages/ui`                                                | UI stays in `apps/web/src/components`                                                   | There is only one UI consumer. A shared UI package would add build configuration without any reuse. It can be extracted if a second app appears.                                                                                                                                     |
| `apps/api/src/guards`, `middleware`, `services` at top level | Guards live in `auth/`, cross-cutting pieces in `common/`, services inside their module | Keeps each module self-contained (NestJS convention) instead of grouping by technical type.                                                                                                                                                                                          |
| `apps/api/tests`                                             | `apps/api/test`                                                                         | NestJS convention.                                                                                                                                                                                                                                                                   |
| One NestJS module per area                                   | One `DomainModule` with a folder per area, plus `AuthModule` and `AssistantModule`      | Projects, workflow, schedule, people, clients and finance are facets of one production model and call each other freely; separate modules would be import bookkeeping without a real boundary. The assistant is separate because it depends on the domain and nothing depends on it. |

## Boundaries

- `packages/shared` has **no** runtime dependencies other than Zod. It must not import Prisma, Nest or React.
- `apps/web` never imports `packages/db`. The browser only reaches data through the API.
- Business rules live in API services and `packages/shared/domain`, never in React components.
- A feature folder may import from `components/`, `lib/`, `hooks/`, `store/` and `packages/shared` — not from another feature's internals (only its public `index.ts`).
